# Distance to established baseline CLI usability

Checkpoint: 2026-10-19. The foundation is substantially implemented, but baseline
usability is not yet established. Successful components and one small successful
task do not establish the whole daily workflow. There is no defensible percentage
or fixed number of remaining runs: the next checks can reveal implementation work.

## What is already supported by evidence

- Interactive coding, repository tools, instruction/history delivery, validation,
  repair, route/fallback and process/session contracts exist. M1 is complete offline.
- Local-model runs have independently correct source/test effects, preserved
  original tests, meaningful companion tests and a passing 3,616-case oracle.
  Their original incomplete/failed workflow verdicts remain unchanged.
- Explicit final qualification of unresolved/unavailable scrutiny is implemented
  and tested. Ten scripted delivery controls include actual validation processes
  through both implement and continuous coding-chat with orchestration enabled.
  This is software-path evidence, not a measured real-reviewer detection rate.

The [roadmap capability and milestone tables](development-roadmap.md#approved-capability-set)
remain authoritative. C1-C6 cover repository/Git, instructions/skills, Python
validation, permitted documentation research, semantics and process/session
continuity. Preserve the accepted privacy/approval/security bar in every gate.

## Shortest responsible sequence

1. Prepare and validate a fresh, bounded integrated task using the revised criteria.
   Verify the actual final task, root snapshot and live stage wiring. The old
   private integrated runner did not enable orchestration: copying it unchanged
   would not exercise the newly qualified scrutiny closeout. Continuous coding-chat
   already supports orchestration; no new production review default is needed.
2. Resolve the first evidenced gap, then complete a small realistic multi-turn
   development case against the existing required continuity/tool outcomes.
3. Finish selected-route approval/tool checks and IDE-host-independent C1-C6
   acceptance. Reuse valid existing evidence and combine compatible checks rather
   than restarting the entire matrix or adding speculative infrastructure.

Each success supports the next stage. Representative quality parity, measured
delegation economics and the ADR-049/050 migration decision remain separate claims.
No paid/client account checks or external transmission are authorized by this
document, and no economics claim can be made from local token counts alone.
Independent unattended supervision remains after baseline, as already prioritized.
